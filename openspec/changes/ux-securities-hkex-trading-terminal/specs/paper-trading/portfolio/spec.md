## Purpose

在模拟成交后以一致事务更新账户、成交和持仓，并提供当前用户可审计的持仓与订单历史。

## ADDED Requirements

### Requirement: 模拟成交必须原子更新资金和持仓

系统 MUST 在一个数据库事务内更新订单宽表中的成交字段、扣减或增加模拟账户余额，并更新持仓数量、可用数量和平均成本；MVP 不要求独立成交表。

#### Scenario: 买入成交

- **WHEN** 服务端撮合一笔合法买入订单
- **THEN** 系统在订单记录写入成交数量和成交价，并扣减账户可用余额
- **AND** 系统增加对应标的持仓并保留平均成本

#### Scenario: 卖出成交

- **WHEN** 服务端撮合一笔不超过可用持仓的卖出订单
- **THEN** 系统在订单记录写入成交数量和成交价，并减少持仓
- **AND** 系统增加账户可用余额

#### Scenario: 事务失败

- **WHEN** 成交、余额或持仓更新任一步骤失败
- **THEN** 系统回滚同一事务的所有变更
- **AND** 不产生孤立成交或半更新持仓

### Requirement: 用户可以查看自己的账户、持仓和订单历史

系统 MUST 提供账户余额、持仓估值、未实现盈亏和订单历史，并在服务端按当前用户过滤。

#### Scenario: 查看持仓

- **WHEN** 已登录用户打开持仓页面
- **THEN** 系统返回代码、名称、数量、可用数量、平均成本、现价、未实现盈亏和估值
- **AND** 行情缺失时显示 `unavailable` 或 `stale`，不伪造盈亏

#### Scenario: 查询订单历史

- **WHEN** 用户按标的、方向、状态或时间查询历史
- **THEN** 系统只返回该用户的订单、成交时间、成交数量、成交价和拒绝原因
