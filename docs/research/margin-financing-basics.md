# 保证金融资、股票质押与风险控制示例

本文用简化数字解释保证金、资产折算率、融资利息、追保线和强平线的常见含义，供产品与系统设计讨论使用。示例比例、利率和阈值均为假设，不代表任何券商的实际规则、报价或投资建议。真实产品须以适用市场、券商合同、风险政策和法律审查为准。

> 项目范围提示：当前 MVP 使用模拟订单，不包含真实融资、股票质押或真实交易。本文是概念说明，不构成已确认的产品规则。

## 1. 保证金与杠杆

保证金是客户用于支持交易的自有资金或合资格资产。融资买股时，客户投入自有资金，券商提供借款，两者共同形成持仓。

假设买入 100,000 港元股票，初始保证金比例为 50%：

| 项目 | 金额 |
| --- | ---: |
| 客户自有资金 | 50,000 港元 |
| 券商借款 | 50,000 港元 |
| 股票市值 | 100,000 港元 |

此时持仓约为自有资金的 2 倍，即 2 倍杠杆。先忽略利息和费用：

- 股价上涨 10%：股票市值变为 110,000 港元，扣除 50,000 港元借款后，净值为 60,000 港元；相对原有 50,000 港元自有资金，盈利 10,000 港元，即 20%。
- 股价下跌 10%：股票市值变为 90,000 港元，扣除借款后净值为 40,000 港元；亏损 10,000 港元，即原有自有资金的 20%。

因此，杠杆会同时放大盈亏，且利息和费用会进一步影响净值。

## 2. 资产折算率与借款额度

券商通常不会把抵押股票的全部市值都视为可用担保价值，而会按证券、市场、流动性、波动性和集中度等因素折算。折算率越低，可计入的抵押价值越少。

假设账户持有两只股票：

| 股票 | 市值 | 折算率 | 折算后抵押价值 |
| --- | ---: | ---: | ---: |
| A | 100,000 港元 | 70% | 70,000 港元 |
| B | 50,000 港元 | 40% | 20,000 港元 |
| 合计 | 150,000 港元 | - | 90,000 港元 |

如果另有规则规定借款上限为折算后抵押价值的 60%，示例借款上限为：

```text
90,000 × 60% = 54,000 港元
```

这里分两步，是为了区分两个不同问题：**折算率**决定券商认可多少抵押价值；额外假设的**借款上限比例**决定最多可借到认可抵押价值的多少。因此本例先把 150,000 港元市值折算成 90,000 港元，再假设最多借其中的 60%，得到 54,000 港元。

60% 只是用于展示两层规则的假设，不是通用券商规则。若某产品规定“借款上限为证券原始市值的 60%”，就应直接按该产品合同的计价基础计算；不能先乘折算率、再乘 60%，除非合同明确要求这两层都应用。反过来，若产品确实把借款上限定义为折算后抵押价值的 60%，才使用本例的 `90,000 × 60% = 54,000`。设计时必须写清楚比例作用于原始市值还是折算后价值，避免重复折算或高估额度。

若 A 股票折算率从 70% 调低到 50%，而市值不变，其折算价值会从 70,000 降至 50,000 港元；在本例“两层比例都适用”的假设下，总折算价值降为 70,000 港元，示例借款上限随之从 54,000 降到 `70,000 × 60% = 42,000 港元`。

## 3. 融资利息

一种常见的简单估算方式是按借款本金、年利率和计息天数计算：

```text
利息 = 借款本金 × 年利率 × 计息天数 ÷ 年计息日数
```

假设借款 100,000 港元，年利率 9%，借款 7 天，按 365 天计算：

```text
100,000 × 9% × 7 ÷ 365 ≈ 172.60 港元
```

借款 30 天的估算利息约为 739.73 港元。真实系统还需明确利率是否浮动、计息日数采用 365 或 360、按自然日还是其他规则计息、最低收费、扣息时间及不同币种的处理方式。

## 4. 追保线

追保线是要求客户补充资金、补入合资格抵押品或偿还部分借款的风险门槛。为便于演示，假设风险比率定义为：

```text
风险比率 = 账户净值 ÷ 股票市值
账户净值 = 股票市值 - 借款余额
```

沿用初始投入 50,000 港元、借款 50,000 港元的例子。假设追保线为 30%，股票市值跌到 70,000 港元：

| 项目 | 金额/比率 |
| --- | ---: |
| 股票市值 | 70,000 港元 |
| 借款余额（忽略利息） | 50,000 港元 |
| 账户净值 | 20,000 港元 |
| 风险比率 | 20,000 ÷ 70,000 ≈ 28.6% |

28.6% 低于假设的 30% 追保线。若只考虑这个简化比率，补入约 1,000 港元现金可使比率回到 30%：

```text
(20,000 + 1,000) ÷ 70,000 = 30%
```

真实追保金额须按券商合同和完整风险模型计算，可能还涉及折算率、其他负债、应计利息、集中度、汇率及补仓期限。

## 5. 强平线

强平线是风险更高时，券商可能卖出部分或全部持仓以降低风险的门槛。沿用上述示例，假设强平线为 20%。当股票市值跌到 62,500 港元：

| 项目 | 金额/比率 |
| --- | ---: |
| 股票市值 | 62,500 港元 |
| 借款余额（忽略利息） | 50,000 港元 |
| 账户净值 | 12,500 港元 |
| 风险比率 | 12,500 ÷ 62,500 = 20% |

触及示例强平线时，券商可能卖出持仓偿还借款。快速下跌、停牌、流动性不足或价格跳空都可能令实际成交价差于触发时价格；强平后也不保证一定没有剩余欠款。强平流程、通知方式和执行权限必须以适用合同和规则为准。

## 6. 股票质押借款

股票质押是以已有股票作担保取得借款，不一定是为了买入更多股票。计算抵押价值时仍可能应用折算率和借款上限。

假设客户已有市值 200,000 港元的股票，折算率为 50%，借款上限为折算价值的 60%：

```text
折算后抵押价值 = 200,000 × 50% = 100,000 港元
示例最高借款额 = 100,000 × 60% = 60,000 港元
```

若股票价格下跌或折算率下调，抵押价值和可借额度会减少。若已有借款超过更新后的风险限额，客户可能需要补充抵押品或还款。质押并不消除股价下跌风险。

## 7. 港美股与多币种风险

若账户同时持有港股和美股，或以一种货币借款、以另一种货币持有抵押品，系统还需处理汇率折算、币种负债和跨市场风险。

例如客户以美元借款，抵押品主要是港股。即使港股价格不变，汇率变化也可能影响折算后的抵押价值；若港股下跌且汇率同时向不利方向变化，风险会叠加。产品规则应明确汇率来源、换算时间、币种折扣、利息币种和还款币种。

## 8. 模拟订单撮合示例

撮合决定一笔买卖订单是否能成交、成交多少、以什么价格成交；保证金计算决定客户需要提供多少自有资金或抵押品。两者有关联（成交会影响现金、持仓和风险敞口），但不是同一套计算。

以下仅说明模拟限价单的成交逻辑，不是本项目已经实现的盘口撮合，也不是保证金或融资规则。假设行情快照如下：

| 买卖盘 | 价格 | 可见数量 |
| --- | ---: | ---: |
| 最优买价（Bid） | 379.90 港元 | 1,000 股 |
| 最优卖价（Ask） | 380.10 港元 | 600 股 |
| 最新成交价（Last） | 380.00 港元 | - |

买入单要和卖方报价（Ask）比较，卖出单要和买方报价（Bid）比较：

- **买入限价 380.00 港元，500 股**：卖方最低报价为 380.10 港元，高于买方最高愿付价，不能立即成交，可留为待处理订单。
- **买入限价 381.00 港元，500 股**：Ask 低于买入限价，满足成交条件。示例可按 Ask 价 380.10 港元成交，而不是按客户允许的最高价 381.00 港元成交；这 0.90 港元/股是相对限价的价格改善。成交金额为 `500 × 380.10 = 190,050 港元`，未计费用。
- **买入限价 381.00 港元，800 股**：若模拟器把快照中 600 股 Ask 数量视作可成交量，则先成交 600 股，成交金额为 `600 × 380.10 = 228,060 港元`；剩余 200 股继续挂单或按订单有效期取消。这是部分成交。真实资金冻结还需明确按剩余订单限价、预计费用和其他风控规则计算。
- **卖出限价 379.90 港元，500 股**：Bid 达到卖方最低接受价，可以示例按 379.90 港元成交，卖出所得为 `500 × 379.90 = 189,950 港元`，未计费用。
- **卖出限价 380.10 港元，500 股**：最高 Bid 只有 379.90 港元，未达到卖方限价，不能立即成交。

最新成交价（Last）只表示最近一笔成交的价格，不保证当前仍有对手盘。例如 Last 是 380.00 港元，并不代表此刻可以按 380.00 港元买入；当前卖方最低报价可能是 380.10 港元。Bid/Ask 和盘口数量更适合模拟限价成交，但前提是行情源确实提供且数据足够新鲜。

**与当前系统的区别：**当前系统检查行情新鲜度和交易时段后，仓储层按数据库 `last_price` 判断：买入限价不低于参考价、或卖出限价不高于参考价，就按参考价全额成交；否则订单成为 `pending`。当前没有使用 Bid/Ask 数量、部分成交、价格队列或挂单后的持续重新撮合，因此上面的盘口示例是改进方向，不应误认为已经上线。

逐步改进时，应先让判价与成交共用同一份有时间戳的行情快照；有可靠 Bid/Ask 时按对手盘判定；再加入可见数量限制、部分成交记录和剩余数量状态。若只有 Last、报价过期或盘口不可用，应明确拒绝模拟成交或使用显式标记的保守规则。公开或延迟行情不等于真实、完整的可执行盘口，模拟成交不能发送到真实市场。

## 9. 出入金渠道与主动风控（FPS/eDDA/CHATS）

主动风控是在资金申请的关键节点提前判断身份、来源、到账状态、可用性和收款去向，而不是等资金已经用于交易或转出后才调查。它与保证金、撮合有关联，但职责不同：出入金改变账户现金；撮合产生模拟或真实成交；保证金规则决定借款和抵押风险。三者应通过统一账务和风险状态协作，不能互相代替。

> 项目范围提示：当前 MVP 使用虚拟账户，不支持真实入金、出金、FPS、eDDA 或 CHATS。以下是未来接入支付/银行渠道时的设计建议，不代表现有能力或已确认的合规政策。

### 产品风控原则：入金低摩擦，出金强审核

产品方向可以是**入金流程尽量简单顺畅，出金审核相对严格**，因为高风险资金若快速转出，可能造成资金流失或妨碍调查。但“低摩擦”不等于跳过身份、银行到账、付款来源和必要合规检查；入金未达到渠道确认条件时，不能提前作为可交易余额。

出金应在不可逆的银行转账前完成必要检查。正常客户应有清楚、可追踪的办理流程；新增收款人、账户安全事件、申报资料与实际资金流显著偏离等情形，可进入管理员审核。AI 只产生风险提示，不自动增加出金障碍或冻结账户；具体审核和限制由获授权的管理员/合规人员按政策决定。

若怀疑资金为赃款或涉及洗钱，系统和客服不能自行把款项“交给警察”、没收资金或仅凭 AI 分数定性。应保留交易与审核记录，升级合规/法律流程，由有权限人员根据适用法律、银行/支付渠道合同及执法机关的合法要求决定是否限制交易、提交报告或配合调查。香港业务是否以及如何向联合财富情报组（JFIU）作可疑交易报告，应由合规和法律顾问按个案及现行要求确认；处理时还须遵守不得不当披露调查信息等适用要求。

### 9.1 资金状态流程

不能把“用户已提交申请”当成银行已到账或出金已完成。入金和出金应分别维护明确状态，并保留每次状态变更及依据：

```text
入金：已发起 → 银行处理中 → 已确认 → 可用
                           ↘ 失败

出金：已申请 → 待管理员审核 → 已批准 → 银行处理中 → 已完成
                       ↘ 管理员拒绝 / 退回
```

入账应依据银行或支付服务商的可信确认，不接受截图、前端成功提示或用户填写的转账参考号作为到账凭证。具体何时可用、是否存在退回窗口，要按渠道合同和结算状态定义。资金变化写入不可随意覆盖的账务流水；失败、退款和冲正应新增对应流水，不删除原记录。回调需要验签/认证、幂等和重复消息去重，避免重复入账或重复出金。**AI 风险预判只产生管理员审核案例，不自动改变入金/出金状态，也不自动冻结资金或账户。**

### 9.2 入金检查

- **付款人匹配**：尽可能核验银行/服务商确认的付款人和平台账户持有人关系；不要仅凭转账备注等自由文本判断身份。
- **来源与行为异常**：新设备登录后突然大额入金、短时拆分多笔、来自无关第三方的款项等，可形成风险预判并提醒管理员审核；AI 结果本身不延迟入账、不要求补资料，也不改变资金状态。
- **到账与可用分离**：银行处理中或状态不确定时，可以展示“处理中”，但不能先增加可交易余额；确认可用后才入账到可用资金。
- **资金闭环监控**：入金后立即买卖并转出到新收款账户、频繁入金后不交易即出金等行为，可组合账户、设备、收款人和时间特征进行审查。

渠道适配需要区别处理：

| 渠道 | 风控与状态设计重点 |
| --- | --- |
| FPS | 使用银行/服务商确认及可获得的付款来源资料；快速到账不代表身份和资金来源风险自动消失，不凭用户凭证入账。 |
| eDDA | 核验扣款授权状态、扣款结果及失败/退回状态；“已发起扣款”不能直接等同“资金已最终可用”。 |
| CHATS | 保存银行参考资料、结算状态并纳入对账；以银行/服务商合同约定的结算确认作为可用依据，不凭用户声明确认。 |

渠道最终性、撤回/退回能力及确认时点必须由合作银行或服务商合同确定；应用不能假设所有渠道的到账语义相同。

### 9.3 出金检查

出金前应检查**可提余额**而非总资产，并扣除未结订单冻结资金、费用、其他负债及适用的限制金额。其余检查可包括：

1. **账户与身份状态**：账户是否有效，有无冻结、待调查或未完成验证状态。
2. **收款人验证**：优先转回已验证且与客户本人匹配的银行账户。新增或更改收款人时，可按独立的基础业务政策要求重新验证；这类政策须与 AI 风险预判分开定义，不能由 AI 分数自动触发。
3. **账户安全事件**：近期更换密码、MFA、手机号、邮箱，或出现新设备、新 IP、异常登录时，AI 可生成风险预判并送管理员审核；是否要求额外验证或暂缓申请由管理员按授权流程决定。
4. **金额与频率**：检查单笔/累计金额、短时频次、拆分交易、账户使用时长和相对历史行为的偏离。
5. **资金路径**：入金后快速出金、短时间内多次更换受益人、入金付款人与出金收款人不一致等信号应组合评估，不能只看单个阈值。
6. **结果确认**：仅在银行/服务商确认成功后标为完成；失败或退回要生成关联的冲正/退回流水并恢复相应可用余额。

例如：账户平时只向已验证的本人账户小额出金；某日从新设备登录、刚改了手机号，随后申请大额转到新账户。AI 只把这些信号整理成案例并提醒管理员；它不会自行暂停申请或要求增强认证。管理员查看证据后，再决定是否要求验证、暂缓本笔申请或采取其他获授权的处置。

### 9.4 管理员审核与审计

AI 风险预判不连接自动放行、拦截、暂缓、退回、冻结或封号动作。模型只输出风险等级、触发信号和建议审核重点；最终处置由有权限的管理员查看证据后决定：

| 管理员审核结论 | 管理员可执行的后续动作 |
| --- | --- |
| 未发现需升级的问题 | 记录审核结论；按原业务流程继续处理 |
| 需要进一步核实 | 管理员要求补充资料或增强认证 |
| 需要暂缓处理 | 管理员按权限暂缓本笔资金申请，并说明理由 |
| 有较强风险证据 | 管理员升级合规调查；账户级限制按授权和审批流程处理 |

管理员审核应有角色权限、理由必填、完整审计记录；高影响操作可要求双人审批。每次决策保存风险提示、证据引用、管理员结论、实际操作、操作人/审批人和时间；日志脱敏，不记录密码、完整支付凭据或无关敏感数据。法律或合规要求的独立硬性拦截应由单独的已批准业务规则执行，不属于 AI 风险分数触发的自动动作，也不能被 AI 分数覆盖。

### 9.5 建议的系统边界

```text
DepositService / WithdrawalService（流程与状态）
  → PaymentChannelAdapter（FPS / eDDA / CHATS 服务商接口）
  → RiskAssessment（仅产出分数、信号与审核案例，不调用资金状态变更）
  → AdminReview（管理员查看证据并决定是否执行授权动作）
  → Ledger（不可覆盖的资金流水）
  → Reconciliation（内部记录与银行/服务商记录核对）
  → Audit（规则、审批、状态变更与关联标识）
```

渠道接入前，应先定义账户与资金数据合同、状态机、幂等键、验签方式、账务分录、事务边界、对账文件、失败/退回处理、迁移和回滚方案。未经明确授权，不连接真实银行渠道，不触发真实扣款或转账。

### 9.6 时间窗口检测、模型告警与管理员审核

可以在规则计算之外增加异常检测模型。模型按多个滚动时间窗口分析账户和资金事件，输出风险分数及可解释的风险信号，再把案例送到管理员审核队列。模型的职责是**风险预判、发现和排序线索**，不是判断客户是否欺诈，也不与任何自动资金/账户处置挂钩。AI 输出不得直接调用放行、拦截、暂缓、退回、冻结、限制账户或封号接口；每个处置由管理员审核后发起并留痕。

可考虑的窗口包括最近 5 分钟、1 小时、24 小时、7 天和 30 天；窗口长度、金额阈值和客户基线要按产品、渠道和客户类型配置。特征可以包括：

- 入金/出金的笔数、累计金额、平均金额、频率变化、拆分模式，以及与账户历史基线的偏差。
- 入金后多快下单、卖出后多快出金，资金是否快速流经账户，以及入金付款人和出金收款人是否一致。
- 新设备/IP、近期密码或 MFA/联系方式变更、账户年龄、收款人新增时间，以及多个账户之间共享的设备或收款资料。
- 渠道状态、失败/退回次数、身份核验结果和已有人工审核事件；只使用合法、必要且经过权限控制的数据。

#### 风险场景线索（不是自动定性）

同一组事件可能有不同解释，模型可分别给出待核查的**场景线索**，不能把线索写成结论：

| 待核查场景 | 可组合观察的线索 | 管理员后续核查方向 |
| --- | --- | --- |
| 疑似账户接管（ATO） | 新设备/IP 登录；近期密码、MFA 或联系方式变更；紧接着新增收款人或申请异常出金；与客户历史行为明显不同 | 由安全/欺诈审核人员核验登录和认证事件、联系客户或要求身份复核；确认是否为本人操作。 |
| 疑似异常资金流/洗钱风险 | 入金付款人与客户关系不明；资金短时间流入又转出；短期拆分交易；多账户共用设备/收款资料；申报资金来源或预期活动与确认资金流明显偏离 | 由合规人员结合客户资料、资金来源解释、渠道信息和完整交易链路判断；依法需要时按内部流程升级或处理。 |

这些线索都可能有合理原因：客户更换手机、家庭/公司账户安排、资产变现或正常资金周转都可能造成相似表现。AI 不认定“账号被盗”或“正在洗钱”，也不生成自动处置；可把一个案例同时标为“账户安全待核查”和“资金流待核查”，由相应管理员/合规人员审核。

#### 指标定义与计算示例

对每个账户和窗口 `W`，先从已确认的资金事件及账户安全事件计算原始指标。至少区分“已发起”“处理中”“已结算/已确认”“已退回”，不可把未结算申请和最终资金混成同一金额：

```text
入金笔数 N_in(W) = 窗口 W 内入金事件数
入金金额 A_in(W) = 窗口 W 内已确认入金金额之和
出金笔数 N_out(W) = 窗口 W 内出金申请/成功事件数（分别统计）
出金金额 A_out(W) = 窗口 W 内相应状态的出金金额之和
```

建议计算这些指标：

| 指标 | 一种可解释的计算方式 | 说明 |
| --- | --- | --- |
| 金额/频率突增 | 当前 `A_in(W)`、`A_out(W)` 或事件数，与同一账户过去相似时段的中位数比较；`偏离倍数 = 当前值 ÷ (历史中位数 + ε)` | 可用过去 8-12 周同星期/时段作基线；新账户没有足够历史时，用相似客群基线并标记低置信度。金额通常先做 `log(1+x)`，降低少数超大值对模型的影响。 |
| 快速出金比例 | `快速出金比例(W, Δ) = 入金确认后 Δ 时间内发生的出金额 ÷ 对应入金额` | 资金是可混同的，不能仅凭时间先后断言某笔出金就是某笔入金。应按账本余额/资金批次建立一致的归因方法，并将结果视为行为信号。 |
| 申报财务状况与资金流偏离 | 优先比较窗口内**外部确认入金/出金**与客户申报的预期月度交易金额区间；若只收集到资产区间，可辅助计算 `外部确认入金金额(W) ÷ 申报流动资产区间上界` | 超出客户申报的交易活动区间或相对流动资产明显偏高时产生告警，不直接认定虚报。总资产不是月交易限额；内部自有账户划转、资金重复周转、资产变现、贷款、业务收入和资料过期都可能造成表面偏离。应区分外部流入、外部流出和内部转账，结合资金来源说明及更新后的客户资料复核。 |
| 付款人与收款人不一致 | 已验证付款人/账户持有人与收款人身份关系的状态：`一致 / 未知 / 不一致` | “未知”不能等同“不一致”，也不能当作零风险；确认不一致应按适用政策走单独规则。 |
| 新收款人风险 | `收款人年龄 = 当前时间 - 收款人首次验证时间`，再按经验证的时间区间映射为 0-100 分 | 具体区间需用运营数据和政策确定；新收款人只是风险信号，不应单独证明欺诈。 |
| 认证变更邻近出金 | `Δt = 出金申请时间 - 最近一次密码/MFA/联系方式变更时间` | 若 `Δt` 落在观察窗口内，模型可提高风险预判并提示管理员；是否要求增强认证由管理员审核决定。事件缺失应标为未知，不得默认“没有变更”。 |
| 失败/退回率 | `失败退回率(W) = 窗口内失败/退回金额 ÷ 窗口内尝试金额`；同时统计笔数比例 | 按 FPS/eDDA/CHATS 分开计算，因为渠道失败语义和结算时点不同。 |

连续指标要映射到统一的 0-100 风险分，可以用历史分位数或稳健统计方法，例如：

```text
偏离分 = clamp(100 × 当前指标在同类历史样本中的分位数, 0, 100)
```

对偏态金额分布，可在 `log(1+x)` 后使用中位数和 MAD（median absolute deviation，中位数绝对偏差）计算稳健偏离度；不要直接假设金额服从正态分布。类别指标可由风险团队定义映射（如“已验证旧收款人”分较低、“新收款人”分较高），但映射必须有版本、理由和验证记录。

一个可解释的初版组合分数可以是：

```text
总分 = Σ(指标分_i × 权重_i) ÷ Σ(有效指标权重_i)
```

例如“快速出金 30% + 金额/频率突增 25% + 新收款人 20% + 认证变更邻近 15% + 失败/退回 10%”。这些权重仅用于展示算法，不能直接作为生产阈值。若某项数据缺失，应标注缺失并按既定缺失策略处理，不能直接当成 0 分；当有效指标太少时应转人工或规则兜底。

#### 为什么选择这五项与风险边界

这五项不是“欺诈指标”的完整清单，而是为了用较少、可解释的信号覆盖五个不同维度：资金流速、行为偏离、资金去向、账户安全和支付结果。设备/IP、付款人与收款人关系、客户申报资料和渠道状态仍可作为上下文证据；身份不符、制裁名单命中等依法必须拦截或升级的条件，应由独立的业务/合规规则处理，不能由综合分数替代。

- **快速出金（示例权重 30%）**：入金确认后短时间出金，直接反映资金是否在审核前快速离开，因此在示例中优先级最高。风险是正常资产变现也可能很快；资金可混同，不能仅凭时间先后断言某笔出金就是某笔入金。
- **金额/频率突增（示例权重 25%）**：相对账户自身历史基线观察行为变化，比单一固定金额阈值更能适应不同客户。风险是新账户缺少历史、季节性或一次性收入会造成误报，基线还可能被异常行为污染。
- **新收款人（示例权重 20%）**：出金目的地发生变化，且银行转账通常不可逆，是目的地风险的重要信号。风险是新增本人、家庭或公司账户可能完全合理；“未知关系”不能直接当成“不一致”。
- **认证变更邻近出金（示例权重 15%）**：密码、MFA、手机号或邮箱变更后紧接出金，能把账户安全事件与资金动作关联起来。风险是更换设备等正常操作也会触发，时间接近不是账户接管的证明；缺失事件必须标为未知。
- **失败/退回率（示例权重 10%）**：反映支付渠道异常、重复尝试或资金路径不稳定。它的噪声较大，银行故障、资料错误、重试以及 FPS/eDDA/CHATS 的结算语义差异都可能造成失败，因此示例权重最低。

30/25/20/15/10 表示治理上的初始优先级，不是统计概率，也没有在本文件中经过历史样本校准。上线前还要验证误报、漏报、审核命中率、人工处理容量和不同客户群体的差异。五项信号可能来自同一事件（例如认证变更、新收款人和快速出金），直接相加会重复计权；还要处理冷启动、数据缺失、渠道状态混淆、基线漂移和被规避等风险。模型只应生成可解释的待审案例，不能自动放行、拦截、冻结或改变出入金状态。

示例：某笔申请的五项指标分依次为 `90、70、100、80、0`，使用上述示例权重，则总分为 `27 + 17.5 + 20 + 12 + 0 = 76.5`。这表示该案例在队列中风险信号较强，**不是有 76.5% 概率欺诈**。动作阈值要在历史回放和影子运行中评估告警量、命中率、误报率、漏报率和人工处理能力后再定。

申报财务状况偏离示例：客户申报的预期月度外部入金为 20,000-50,000 港元，过去 30 天经渠道确认的外部入金为 180,000 港元。该情况超过申报区间，AI 只生成提示，由管理员决定是否要求更新资料或进一步复核；管理员需先排除自有账户划转被误归为外部入金、资产出售、贷款到账、一次性收入或客户资料已过期等原因。系统不应只因 `180,000 ÷ 50,000 = 3.6` 就自动封号或判定欺诈。

身份不符、制裁名单命中或其他依法必须拦截/升级的条件应由独立、经批准的业务/合规规则处理；它们不是 AI 风险预判，也不由综合模型分数决定。模型阈值的选择也不能只追求命中率，应结合客户误伤成本、审核容量和合规要求。

模型结果只生成如下待审案例，不自动执行建议动作：

```text
风险分数：高
待核查线索：账户接管疑点；异常资金流疑点（均非定性结论）
触发信号：新设备登录；联系方式刚变更；新收款人；入金后短时间申请大额出金
审核提示：安全审核核验账户操作；合规审核核验资金来源与流向
自动处置：无；出金状态不因模型告警而改变
关联事件：入金 ID、出金申请 ID、设备事件 ID、规则/模型版本
```

管理员工作台可展示告警、相关事件、数据新鲜度、模型/规则版本和审核历史。管理员可在权限范围内选择“关闭告警、要求补充验证、暂缓本笔出入金、升级合规调查、申请账户级限制”等动作；系统须要求管理员确认并记录理由。账户级限制须遵循独立授权和审批流程。AI 案例创建、分数变化或模型重跑都不得自行触发这些动作。

模型治理建议：

- 初期可用影子模式验证模型提示质量；生产中模型始终只做预判和管理员提示，不论验证结果如何，都不自动拦截资金或改变账户状态。
- 使用经调查确认的欺诈/异常案例作标签；人工“放行”不一定等同于真实安全，不能把未经核实的审核结果直接当成高质量标签。
- 按时间切分训练集、验证集和测试集，避免未来信息泄漏；分别监控误报率、漏报率、审核命中率、客户申诉/解除限制率和不同客户群体的表现。
- 保存特征口径、数据来源、阈值、模型版本和决策记录；监控数据漂移，模型更新须经过回归验证和审批，并保留回退到规则策略的能力。
- 对管理员仅展示履职所需的信息，限制敏感资料访问；日志脱敏，模型评分不能代替 AML/合规团队依法作出的判断或申报决定。

该能力需等真实支付渠道、账务和管理员权限体系获批后再实施。当前 MVP 没有真实资金事件、模型训练数据或管理员资金审核工作流，因此不能声称已有此风控能力。

## 10. 关系总览

```text
证券市值 × 资产折算率 = 折算后抵押价值
折算后抵押价值 × 借款上限比例 = 示例可借额度
借款本金 × 利率 × 天数 = 应计融资利息（按约定日数折算）
市场下跌 / 折算率下调 / 负债增加 → 风险比率下降
风险比率触及追保线 → 要求补救
风险比率触及强平线 → 可能强制减仓或平仓
```

上述公式仅用于说明概念。具体产品设计应分别定义初始保证金、维持保证金、证券折算率、追保规则、强平规则、估值与汇率时点、费用、通知和争议处理，并由合规、法律及风险团队审核。
